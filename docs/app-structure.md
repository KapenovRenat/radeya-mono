# Структура фронта: маршруты, layout, компоненты

Next.js App Router, каталог — `front/src/app/`. Перечень страниц одной строкой —
в [index.md](../index.md).

---

## Дерево маршрутов

```
front/src/app/
├── layout.tsx                      # корень: шрифты, провайдеры, lang="ru"
├── providers.tsx                   # Redux-провайдер
├── globals.css
│
├── (shop)/                         # магазин, тема theme-shop
│   ├── layout.tsx
│   └── page.tsx                    → /
│
└── dashboard/                      # админка, префикс /dashboard
    ├── layout.tsx                  # общая обвязка: theme-dashboard
    ├── (auth)/
    │   ├── layout.tsx              # форма по центру, без сайдбара
    │   └── login/page.tsx          → /dashboard/login
    └── (main)/
        ├── layout.tsx              # сайдбар и рабочая область
        ├── page.tsx                → /dashboard
        ├── accounts/
        │   ├── layout.tsx          # RoleGuard: только ADMIN
        │   ├── page.tsx            → /dashboard/accounts
        │   └── _components/        # только для этой страницы
        └── kaspi-sync/
            ├── layout.tsx          # RoleGuard: только ADMIN
            ├── page.tsx            → /dashboard/kaspi-sync
            └── _components/
```

Ограничение по ролям стоит в `layout.tsx` раздела, а не на странице: так оно
накроет все будущие подстраницы, и его нельзя будет забыть на новой.

Папка с префиксом `_` исключена из роутинга: в неё складываются компоненты,
нужные одной странице. Маршрут создаёт только файл `page.tsx`.

### Как читать скобки

Папка **в скобках — группа маршрутов**: в URL не попадает, нужна только для того,
чтобы дать своей ветке отдельный layout. Папка **без скобок попадает в адрес**.

Отсюда устройство админки: `dashboard` без скобок даёт префикс `/dashboard`,
а `(auth)` и `(main)` — две разные обвязки внутри одного префикса.

### Почему сайдбар не в `dashboard/layout.tsx`

Вложенные layout в App Router **не заменяют родительский, а оборачиваются в него**.
Положи сайдбар на уровень `dashboard/layout.tsx` — он появится и на форме входа,
убрать его оттуда будет уже нечем.

Поэтому уровни разведены:

| Уровень | Что даёт | Кому |
|---|---|---|
| `dashboard/layout.tsx` | Класс темы `theme-dashboard` | всей админке, включая вход |
| `dashboard/(main)/layout.tsx` | Сайдбар, рабочая область | разделам админки |
| `dashboard/(auth)/layout.tsx` | Форма по центру, `max-w-sm` | входу |

## Темы

Токены объявлены в `front/src/styles/themes.css` **только внутри классов**
`.theme-shop` и `.theme-dashboard`; блока `:root` там нет. Значит страница без класса темы
остаётся без переменных, и цвета молча не применяются.

Класс вешается на layout своего раздела: магазин — в `(shop)/layout.tsx`,
админка целиком — в `dashboard/layout.tsx`.

Тёмный вариант — `.dark .theme-shop` и `.dark .theme-dashboard`, то есть переключается
классом `dark` выше по дереву.

## Вход в дашборд — как это устроено на фронте

Токен нигде не хранится. Сервер ставит httpOnly-куку, `baseApi` отправляет запросы
с `credentials: "include"`, браузер прикладывает куку сам. В `localStorage` не пишется
ничего: оттуда значение достаётся скриптом, из httpOnly-куки — нет.

| Файл | Что делает |
|---|---|
| `features/auth/auth-api.ts` | `login`, `logout`, `me`; общий тег кэша `Auth` |
| `features/auth/use-auth.ts` | `useAuth()` — текущий пользователь; `useLogout()` — выход |
| `features/auth/use-login-form.ts` | Состояние формы входа и отправка |
| `features/auth/auth-guard.tsx` | Не пускает в разделы админки без входа |
| `shared/api/error-message.ts` | Текст ошибки из ответа RTK Query |

**Отдельного слайса с пользователем нет.** Кэш RTK Query и так лежит в сторе,
`useAuth()` читает его из любого компонента. Копия в слайсе была бы вторым источником
правды и однажды разошлась бы с первым.

**Тег `Auth` связывает три эндпоинта:** после `login` и `logout` запрос `me`
перезапрашивается сам, руками состояние обновлять не нужно.

**`AuthGuard` — защита интерфейса, а не безопасность.** Реальную проверку делает сервер
на каждом запросе. Смысл компонента в том, чтобы не показывать пустой дашборд с ошибками
там, где данных всё равно не будет.

## Два входа

Вход сотрудника и вход клиента магазина — **разные страницы с разными темами**,
они не переиспользуются:

| Кто | Адрес | Статус |
|---|---|---|
| Сотрудник | `/dashboard/login` | заглушка, форма на этапе 1 |
| Клиент магазина | в разделе магазина, адрес не выбран | появится вместе с витриной |

Причина в модели данных: `User` и `Customer` — разные сущности со своими правилами входа,
см. [data-model.md](data-model.md).

## Компоненты

| Где | Что лежит |
|---|---|
| `front/src/components/<имя>/` | Свой компонент: `tree-list.tsx` + `style.module.scss`. Образец — `price-tag/` |
| `front/src/features/<фича>/` | Логика фичи, включая эндпоинты RTK Query |
| `front/src/shared/api/` | `baseApi` — единая точка RTK Query и теги кэша |
| `front/src/lib/utils.ts` | `cn()` — склейка классов Tailwind |
| `front/src/lib/` | Общая логика без привязки к фиче: `format.ts`, `use-pagination.ts` |

`usePagination()` — постраничный показ списка, который уже целиком в памяти. Отдаёт
срез страницы, номера кнопок с разрывами (`1 … 49 50 51 … 133`) и диапазон «показано
с — по». Для серверной выборки не годится: там страницу отдаёт запрос, а не срез
массива. Первым его использует таблица разбора выгрузки Kaspi.

Правило по цветам: **только токены темы**, без хардкода. Хардкод перестаёт переключаться
между магазином и админкой и между светлой и тёмной темой.

### Готовых UI-китов нет

Все компоненты пишутся сами. shadcn/ui, его CLI, `tw-animate-css`
и `class-variance-authority` из проекта удалены. Осталось: Tailwind для раскладки,
Sass для внутренностей компонентов, `cn()` для склейки классов, Lucide для иконок.

Base UI лежит в зависимостях, но пока не используется — он не приносит стилей, только
поведение и доступность для модалок и выпадающих списков. Понадобится, когда дойдём
до модального окна складов.

### Различия между магазином и админкой

Два механизма, применяются по ситуации:

**Тема** — когда отличается только внешний вид. Один компонент, значения токенов
переопределены в `.theme-shop` и `.theme-dashboard`. Ничего передавать не нужно,
компонент не знает, где он стоит. Образец — `price-tag/`.

**Проп `variant`** — когда отличий больше, чем цвет: другие размеры, отступы, состав
элементов. Значения — `"shop" | "admin"`:

```tsx
<Button variant="admin">Сохранить</Button>
```

```tsx
className={cn(styles.button, styles[variant])}
```

в `style.module.scss` при этом лежат `.shop { … }` и `.admin { … }`.

Если отличается и разметка, и поведение — это уже два разных компонента, а не варианты
одного. Например карточка товара на витрине и строка товара в таблице админки.

## Каталог с деревом папок — логика готова, вёрстка ожидается (18.09.2026)

Планируемый маршрут: /dashboard/products. Страница и её разметка ещё не созданы;
пользователь верстает их самостоятельно. Не считать этот маршрут работающим.

### useProductCatalog
Назначение — логика таблицы каталога и дерева пользовательских папок.
- Тип: хук для будущего раздела dashboard, доступ ADMIN.
- Данные: GET /api/categories, GET /api/products/variants, PATCH /api/products/category.
- Ключевые компоненты: пока отсутствуют; подключается под AuthGuard/RoleGuard ADMIN.
- Файл: `front/src/features/products/use-product-catalog.ts`.
- API: `front/src/features/products/catalog-api.ts` и
  `front/src/features/categories/categories-api.ts`.

Инструкция по подключению к вёрстке:
1. Слева всегда первым вывести allProducts. Нажатие вызывает selectCategory(null).
   Ниже рекурсивно отрисовать categories и children. Выбор названия вызывает
   selectCategory(id); раскрытие ветки — toggleCategory(id), состояние — expandedCategoryIds.
2. Создать форму через useCreateCategoryForm(catalog.onCategoryCreated).
   Кнопка «Создать категорию» вызывает form.open(catalog.categoryId): при выборе
   «Все товары» создаётся корневая папка, при выборе папки — подпапка.
   Показывать родителя в форме; для корневой категории выбирать «Все товары».
   Поле связано с name/setName, сохранение с submit(), закрытие с close().
   При отправке HTML-формы отменить её стандартный переход. На время isSaving
   блокировать повторное сохранение и закрытие; ошибка выводится из error.
   После успеха дерево обновляется, созданная папка выбирается, родитель раскрывается.
3. Справа вывести items: одна строка на артикул, ключ строки variantId.
   Названия «Угловые диваны» и «Прима 320 Угловой» — обычные папки Category;
   создание второй не создаёт товар. Товары появляются после переноса в эту папку.
4. Поле поиска: search/setSearch. Задержка 300 мс, поиск выполняет сервер.
   Переключатель размера страницы: pageSizes (10/20/50), setPageSize(number).
   Переход между страницами: setPage(number). Число страниц — totalPages;
   активная страница — page из ответа. Срез массива на фронте не делать.
5. Показывать загрузку по isLoading, ошибку по error, пустую таблицу — только
   после успешного ответа. Ошибки дерева: categoriesError; повтор — reloadCategories.
   Повтор списка — reload. При смене папки, поиска или размера страницы выбор
   строк очищается; при смене папки и размера сбрасывается страница.
6. Чекбоксы связать с selectedProductIds и setProductSelected(productId, checked);
   «выбрать страницу» — selectPage(checked). Все строки одного Product выделяются
   вместе. Перенос меняет категорию всего товара вместе со всеми модификациями:
   это нужно явно написать возле действия. Выбор ограничен текущей страницей.
7. В действии «Переместить» выбрать целевую папку и вызвать moveSelected(id).
   Отдельный вариант «Без категории» вызывает moveSelected(null).
   Результат: moveResult (число изменённых товаров), ошибка: moveError.
   На время isMoving блокировать кнопку и чекбоксы. После успеха таблица обновляется.
8. Статус строки status и статусы площадок listings[].status — разные значения.
   Денежные строки форматировать для показа; quantity=null показывать как «не указан».
   Пустые картинка, категория и ткань требуют состояния отсутствующих данных.

- В пустой базе виден «Все товары», таблица пуста, страниц 0, выбранная страница 1.

- Повтор имени в том же родителе (включая другой регистр) даёт 409;
  такое же имя в другом родителе разрешено. Пустое имя и «Все товары» запрещены.
- В «Все товары» видны импортированные артикулы без категории, включая архивные.
- Выбрать товары, перенести в «Прима 320 Угловой»: они видны в этой папке,
  в «Угловые диваны» и в «Все товары», но отсутствуют в «Кресла».
- Если у Product несколько модификаций, проверить перенос всех, а не одной строки.
- Поиск на странице 2 находит артикул из всего выбранного поддерева и возвращает
  страницу 1; проверить часть названия, артикул, регистр и буквальные %/_.
- Проверить 10/20/50, отсутствие результатов, перенос последней строки последней
  страницы, быстрое переключение папок и поиск при медленной сети.
- В ответе списка нет purchasePrice, kaspiUpdates и полной галереи; неизвестные
  остатки остаются null. Без сессии API даёт 401, с ролью ниже ADMIN — 403.

## Loader — общий индикатор загрузки

- Тип: переиспользуемый компонент для страницы и содержимого кнопки.
- Данные: не обращается к API; родитель показывает его во время загрузки.
- Файл: `front/src/components/loader/tree-list.tsx`.
- Стили: `front/src/components/loader/style.module.scss`.
- Пропсы: `label?: string` (по умолчанию «Загрузка ...»), `size?: number | string`
  (диаметр кольца, по умолчанию "1.25em"), `hideLabel?: boolean` (по умолчанию false),
  `className` и нативные атрибуты span, кроме children. Числовой size задаётся
  в пикселях, строковый — с CSS-единицами, например "2rem". Размер текста не меняется.
  hideLabel скрывает видимую надпись и отключает таймер букв; label остаётся
  доступным скринридеру. Например: `<Loader size={32} hideLabel />`.
- Слева вращается кольцо из четырёх сегментов, справа выводится label. Цвет кольца
  и подсветки букв — #f23428 по прямому запросу пользователя (локальная переменная
  --loader-accent). Цвет и размер текста наследуются от страницы или кнопки;
  диаметр кольца задаётся size и по умолчанию зависит от размера шрифта.
  Буквы подсвечиваются по одной слева направо, по 160 мс на символ, затем цикл
  повторяется. Активная буква переключается клиентским таймером React, цвет задаётся
  классом letterActive без CSS-функции linear(). При смене label цикл начинается
  с первой буквы. Таймер очищается при размонтировании и смене текста; настройка
  уменьшения движения отслеживается через matchMedia и останавливает таймер. Внешних отступов
  и фиксированного размера контейнера нет; положение на странице задаёт родитель.
- Доступность: role=status, aria-live=polite, aria-atomic=true; декоративный
  индикатор и анимированные буквы скрыты от скринридера, ему доступна отдельная
  цельная строка label. При prefers-reduced-motion обе анимации отключаются.
- Подключение: именованный импорт Loader из `@/components/loader`.
  Для страницы использовать Loader без label либо с нужным текстом;
  внутри Button на время запроса заменить обычное содержимое на Loader,
  например с label «Сохранение». Самой кнопке выставить disabled и aria-busy
  по состоянию запроса. Компонент не блокирует действия самостоятельно.
- Страницы и кнопки автоматически не изменены; компонент готов к подключению.
- Проверка пользователем: стандартный и пользовательский текст, красное кольцо
  из четырёх сегментов, последовательная подсветка букв, размеры 16/32/48 пикселей,
  скрытие надписи через hideLabel, работа внутри кнопки
  и отключение обеих анимаций при
  включённом уменьшении движения. Команды и тесты агентом не запускались.
