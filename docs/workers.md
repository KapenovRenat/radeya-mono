# Воркеры — фоновые задачи

Фоновые процессы, которые работают без человека: забирают заказы Kaspi,
шлют уведомления поставщикам, следят за собой. Здесь — решения пользователя
(01.10.2026), устройство и порядок работ. Telegram-часть старой админки,
на которую опираемся, — [telegram-bot.md](telegram-bot.md).

## 2. Устройство

### Процессы

- **`server/src/worker.ts`** — отдельный процесс (`npm run worker`), рядом с API.
  Падение воркера не роняет API, а перезапуск API не обрывает цикл. На боевом
  сервере — второе приложение PM2.
- Запускается только при `WORKERS_ENABLED=true` в `.env`. Локально по умолчанию
  выключен: копия боевой базы с галочкой «Работает» иначе начала бы тянуть
  заказы и слать поставщикам с ноутбука.
- **API следит за воркером** (`worker-monitor.ts`): воркер раз в 15 секунд пишет
  «пульс». Пульса нет дольше 2 минут при включённом воркере — событие «воркер
  не отвечает» и оповещение разработчику; пульс вернулся — «снова на связи».

### Цикл

```
читаем настройки из базы
  выключен → ждём, проверяя настройки каждые 15 с
  включён  → цикл:
      блокировка PostgreSQL (одна на воркер и ручную кнопку синхронизации)
      заказы за период → сравнение со старым → события
      состав новых заказов (до 20 за цикл, свежие первыми)
      дата прибытия из кабинета — активным заказам (новые сразу, остальные раз в час)
      [этап 3] отправка поставщикам
  → ждём интервал (настройки сохранили — пересчитываем сразу)
```

- **Наложений нет:** следующий цикл планируется после конца текущего.
- **Потолок цикла — 10 минут** (`WORKER_RUN_TIMEOUT_MS`): дольше — цикл
  прерывается, событие «превышено время», дальше по расписанию.
- **Ошибка цикла** воркер не останавливает: событие, следующий цикл по расписанию.
  Три ошибки подряд — оповещение разработчику; первый успешный после них —
  «восстановился».
- **Падение процесса** — PM2 поднимает заново. Воркер при старте видит,
  что прошлый процесс не остановился штатно, — событие «перезапуск после сбоя».
- **Ручная кнопка синхронизации** на странице заказов берёт ту же блокировку.
  Занято воркером — 409 «повторите через минуту».

### Журнал

Пишется только то, что произошло; «цикл прошёл, ничего нового» — нет
(иначе 720 пустых строк в сутки). Номер заказа и даты хранятся копией —
журнал должен остаться как был. Фильтр по названию товара ищет по текущему
составу заказа: так находятся и события, записанные до загрузки состава.

## 3. Этапы

1. **Каркас и заказы** — процесс, цикл, блокировка, пульс и наблюдение,
   настройки и состояние, блок «Воркеры» в настройках, события заказов,
   состав новых заказов, оповещения разработчику, Telegram ID поставщиков.
2. **Журнал в интерфейсе** — страница с таблицей, пагинацией и фильтрами.
3. **Telegram поставщикам** — карточки-картинки, правила задержки и часов,
   отмены и возвраты, анти-дубль.

## 4. Где что лежит

```
server/src/worker.ts                  # процесс: npm run worker [-- orders ...]
server/src/modules/workers/
├── engine/                           # общее для всех воркеров
│   ├── worker-engine.ts              # startWorkers(): циклы, пульс, потолок, остановка
│   ├── worker-monitor.ts             # наблюдатель пульса в процессе API
│   ├── worker-settings.service.ts    # настройки и состояние
│   ├── worker-events.service.ts      # журнал
│   ├── worker-alerts.ts              # оповещения разработчику
│   └── worker.constants.ts           # тайминги движка
├── jobs/
│   ├── index.ts                      # реестр WORKER_JOBS
│   └── orders/                       # воркер ORDERS
│       ├── orders.job.ts             # цикл: шаги по порядку
│       ├── sync-orders.step.ts       # 1. заказы и изменения
│       ├── load-entries.step.ts      # 2. составы
│       ├── arrival-dates.step.ts     # 3. даты прибытия из кабинета
│       ├── orders.constants.ts
│       └── dispatch/                 # 4. отправка в Telegram
│           ├── dispatch.step.ts      # шаг: выключено? окно? токен и шрифты есть?
│           ├── dispatch-followups.ts # отмены и возвраты — первыми
│           ├── dispatch-new.ts       # новые заказы: пропуск, ожидание даты, отправка
│           ├── recipients.ts         # кому: группа Астаны или поставщик
│           ├── send-dispatch.ts      # одна карточка: анти-дубль, повторы
│           ├── dispatch-data.ts      # выборка заказа и данные карточки
│           ├── order-card.ts         # карточка: Satori → SVG → PNG (resvg)
│           ├── card-fonts.ts, card-image.ts
│           ├── send-window.ts        # дни недели и 8–17 по Астане
│           └── dispatch.constants.ts
└── workers.controller.ts / routes / schemas   # API настроек — общий
```

**Новый воркер:** ключ в `WORKER_KEYS` и название в `WORKER_TITLES` (shared) →
папка `jobs/<имя>/` с `<имя>.job.ts` → строка в `jobs/index.ts`. Карточка
в «Настройках → Воркеры» появится сама.

**Запуск из корня проекта:** `npm run dev:worker` (все воркеры) или
`npm run dev:worker -- orders` (выбранные) — рядом с `dev:server` и `dev:front`,
в отдельном терминале. Внутри это `npm run worker --workspace=server`.

`npm run worker` — все воркеры реестра в одном процессе (на VPS 1 ГБ
каждый Node-процесс на счету). У каждого свой цикл, настройки, состояние и пульс —
галочка или ошибка одного не задевает другие. `npm run worker -- orders` —
только указанные: если воркер станет тяжёлым, его можно вынести отдельным
приложением PM2. Штатная остановка одна на процесс — стирает пульс всем.

## 5. Этап 3 — отправка в Telegram (01.10.2026, не проверено пользователем)

Шаг 4 цикла, `jobs/orders/dispatch/`. Порядок за цикл:

1. Выключено (`supplierNotifyEnabled`) — ничего. Нет `TELEGRAM_BOT_TOKEN` или
   шрифтов карточки — ничего, событие «Отправка невозможна» и оповещение
   разработчику раз в час.
2. Вне окна (отмеченные дни, 8:00–17:00 по Астане) — ничего: кандидаты дождутся
   окна, ночные уйдут утром, субботние при выключенном воскресенье — в понедельник.
3. **Отмены и возвраты** уже отправленных позиций — тому же получателю (снимок),
   одна отмена на позицию: «в пути» → «Забрать с Zammler в г. X», клиентом →
   «Складировать», возврат (`RETURNED`) → «Принять возврат».
4. **Новые заказы:** оформлены после точки отсечки (момент включения галочки),
   прошла задержка, старые первыми, до 30 заказов:
   - закрылся до отправки (отмена, возврат, доставлен) → позиции «не отправлено»;
   - Kaspi Доставка → дата сдачи перечитывается из кабинета (если старше 15 мин);
     её нет — ждём, событие раз в час;
   - получатель: в наличии со склада с группой → группа; в наличии с Астаны без
     группы → ждём; иначе поставщик товара; нет Telegram ID или поставщика —
     событие раз в час, повтор каждый цикл (поправят — уйдёт без перезапуска);
   - по карточке на позицию.
5. Не больше 10 сообщений за цикл, пауза 1,5 с. Сбой — повтор в следующем цикле,
   5 попыток, дальше «не удалось» и оповещение разработчику.

**Анти-дубль** — `OrderDispatch`, уникальность «позиция + вид» (`NEW`, `CANCEL`,
`RETURN`). Строка заводится до отправки; не «ждёт» — второй раз не шлём.

**Карточка** — Satori + `@resvg/resvg-js`, 600×800. Фон: предзаказ — тёмно-красный,
наличие — тёмно-зелёный, отмена и возврат — тёмный с красной плашкой. Строки:
«ЗАКАЗ #6593 (1083386593)», точка продаж, «Отгрузка на Zammler в г. …» /
«Своя доставка · г. …» / «Самовывоз», «Дата сдачи: 27 сентября» (только Kaspi
Доставка), название товара как в каталоге (× N при количестве больше одного),
«Основная ткань», «Артикул изделия», действие у отмены и возврата. Фото —
крупное из Kaspi, JPEG/PNG, не скачалось — «Нет фото товара». **Эмодзи старых
карточек (🚨, ✅) не рисуются** — Satori нужен отдельный набор картинок; при
необходимости добавим.

**Шрифты** — Roboto `.woff` (латиница и кириллица, 400/700/900) в
`server/assets/fonts/`, в репозитории. Команда скачивания — deployment.md.

**Шрифты в Satori:** латиница и кириллица зарегистрированы под **разными именами**
(`Roboto`, `Roboto Cyrillic`). Под одним именем Satori берёт только первый файл
нужной жирности — кириллица выходила квадратами (01.10.2026).

**Проверка без живого заказа** — «Проверка отправки» в карточке воркера:
выдуманный заказ с диваном из каталога, любой вид карточки, плашка «ТЕСТ — НЕ ЗАКАЗ»
(`POST /api/workers/orders/test-card`). На один ID или всем с Telegram ID — группе
Астаны и поставщикам, с подтверждением; итог по каждому получателю с ответом Telegram.
В строке состояния — почему последний цикл ничего не отправил: вне окна, ждут
дату сдачи, некому слать, закрыты до отправки, не удалось.
