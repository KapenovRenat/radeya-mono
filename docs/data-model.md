# Модель данных

Схема Prisma — `server/prisma/schema.prisma`. Здесь описано назначение моделей, значимые
поля и принятые решения. Перечень моделей одной строкой — в [index.md](../index.md).

---

## Общие правила

- **Идентификаторы — UUID**, а не автоинкремент. Последовательный id выдаёт объём базы
  наружу и упрощает перебор чужих записей по URL.
- **Пароли только хешируются**, алгоритм — argon2id. Поле называется `passwordHash`:
  шифрование обратимо, хеш — нет, и имя поля должно об этом напоминать.
- **Учётные записи не удаляются, а отключаются** флагом `isActive`. Удаление рвёт ссылки
  в журнале действий и в заказах.
- **Имена таблиц и колонок — как в схеме Prisma**, без `@@map`. Единственный путь к базе —
  Prisma Client; сырой SQL пишется редко и только параметризованный.

---

## User — сотрудник

Вход в дашборд по логину. **Саморегистрации нет:** учётные записи заводит админ.
Первый пользователь создаётся, пока таблица пуста, — проверка и вставка выполняются
в одной транзакции, иначе два одновременных запроса создадут двух админов.

| Поле | Тип | Заметки |
|---|---|---|
| `id` | `String` UUID | Первичный ключ |
| `login` | `String` уникальный | Латиница, цифры и `. _ -`, нижний регистр. Нормализуется до записи |
| `passwordHash` | `String` | argon2id. Наружу не отдаётся никогда |
| `name` | `String` | Имя сотрудника |
| `position` | `String` | Должность, произвольный текст. Заполняет админ при создании |
| `role` | `UserRole` | Без значения по умолчанию — выбирается явно |
| `isActive` | `Boolean` = `true` | Отключение вместо удаления |
| `createdAt` / `updatedAt` | `DateTime` | |
| `createdById` | `String?` UUID | Кто завёл. Self-relation `UserCreatedBy`, `onDelete: SetNull`. У первого админа пусто |

Индексы: уникальный на `login`, обычный на `role` — по нему строится список сотрудников.

### enum UserRole

`ADMIN` · `MANAGER` · `SELLER`

Значения обязаны совпадать с `USER_ROLES` в `shared/src/constants/roles.ts` — там же
лежат подписи для интерфейса. Роль проверяется на сервере; скрытая кнопка в интерфейсе
защитой не является.

---

## Customer — клиент магазина

Регистрируется сам с витрины. **Отдельная сущность и отдельный вход**, не смешивается
с `User`: у клиента нет ни роли, ни должности, а права сотрудников к нему неприменимы.
Одна таблица на оба типа означала бы кучу пустых полей и проверку «а это точно сотрудник?»
в каждом запросе.

| Поле | Тип | Заметки |
|---|---|---|
| `id` | `String` UUID | Первичный ключ |
| `login` | `String` уникальный | Как у сотрудника |
| `passwordHash` | `String` | argon2id |
| `name` | `String` | Имя клиента |
| `phone` | `String` уникальный | **Обязательный.** Нормализуется до записи в `+7XXXXXXXXXX` — иначе `+7 777 123-45-67` и `87771234567` окажутся разными значениями и уникальность не сработает |
| `email` | `String?` уникальный | **Необязательный.** PostgreSQL допускает любое количество `NULL` в уникальном индексе, поэтому «нужен не всем, но не повторяется» — это одно поле без ухищрений |
| `isActive` | `Boolean` = `true` | |
| `createdAt` / `updatedAt` | `DateTime` | |

## Session — сессия сотрудника

В куке лежит **только идентификатор**, всё состояние — в этой таблице.
Отсюда главное свойство: сессию можно погасить мгновенно, удалив строку.
С подписанным токеном так не выйдет — он действует до истечения срока,
и уволенный сотрудник остаётся в системе.

| Поле | Тип | Заметки |
|---|---|---|
| `id` | `String` UUID | Он же значение куки `radeya_sid` |
| `userId` | `String` UUID | `onDelete: Cascade` — удалили пользователя, сессии ушли |
| `expiresAt` | `DateTime` | 7 дней от создания |
| `createdAt` | `DateTime` | |
| `userAgent` | `String?` | Для раздела «активные сессии» и разбора инцидентов |
| `ip` | `String?` | |

Индексы: `userId`, `expiresAt`.

Проверка при каждом запросе смотрит и срок, и `isActive` пользователя: отключили
сотрудника — его открытая вкладка перестаёт работать на следующем же запросе.

## AuditLog — журнал действий

Только вставка и чтение. Ни `update`, ни `delete` из кода: журнал, который
можно править, журналом не является.

| Поле | Тип | Заметки |
|---|---|---|
| `id` | `String` UUID | |
| `at` | `DateTime` | Когда |
| `userId` | `String?` UUID | Пусто у действий до входа — например неудачной попытки |
| `userLogin` | `String` | **Снимок** на момент действия |
| `userRole` | `String` | **Снимок** на момент действия |
| `action` | `String` | Значение из `AUDIT_ACTIONS` в `shared` |
| `entityType` / `entityId` | `String?` | Над чем действие |
| `before` / `after` | `Json?` | Состояние до и после. Пароли и хеши сюда не попадают |
| `ip` | `String?` | |

Индексы: `at`, `userId`, `action`.

**Связи с `User` намеренно нет.** Логин и роль хранятся копией: иначе после
переименования или смены роли вся прошлая история покажет сегодняшние значения,
а восстановить исходные будет неоткуда.

Запись делает `logAction()` из `server/src/lib/audit.ts`. Сбой записи не роняет
основную операцию — ошибка уходит в логгер, действие проходит: журнал не должен
обрушивать работу системы.
