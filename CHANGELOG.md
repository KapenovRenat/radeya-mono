## 2026-09-15

**Загрузка каталога из кабинета Kaspi**
- Разведан внутренний JSON кабинета: `mc.shop.kaspi.kz/bff/offer-view/list?m=&p=&l=&a=`,
  ответ вида `{ data: [...], total: 694 }`. Он оказался надмножеством XML-выгрузки:
  в нём есть картинки, штрихкод, категории, скидка, `masterSku`, `familyId`
- `POST /api/kaspi-catalog/fetch` — обход двух режимов за вызов (в продаже и архив),
  по 100 товаров, пауза 500 мс между обращениями. **В базу не пишет**
- Кука сессии вставляется в поле на странице и хранится только в памяти процесса:
  ни в `.env`, ни в базу, ни в логи, ни в журнал действий
- Полнота проверяется по `total` из ответа; обрыв возвращает частичный результат
  с номером страницы, чтобы не терять уже полученное
- `toCabinetOffer()` — маппинг в наш DTO: ~300 цен по городам сворачиваются в одну.
  Спорные места (цена расходится по городам, несколько чисел в `familyId`,
  нет артикула) помечаются проблемой, а не разбираются наугад
- Таблица товаров: картинки, штрихкод, цены со скидкой, размер, склады, статус.
  Поиск по артикулу и обоим названиям, фильтр по статусу и по проблемам

**Справочник складов**
- Модель `Warehouse`, миграция `warehouses`: код `PP3`, `kaspiStoreId`, КАТО, наше название
- `GET /api/warehouses`, `POST /api/warehouses/import-kaspi` — импорт из предпросмотра
  выгрузки. Повторяемый: сверка по `code`, наше название и заполненный город
  выгрузкой не перезаписываются, пропавшие склады не удаляются

**Пагинация**
- `usePagination()` в `front/src/lib` — постранично, 10/20/30, номера с разрывами.
  Заменила кнопку «Показать ещё» в таблице разбора выгрузки

**Документация**
- `docs/kaspi-api-integration.md`: разделы 10–12 — маппинг всех полей JSON, три цены
  и три идентификатора, дерево папок из `categoryPathCodes` и `familyId`,
  чек-лист проверенного и открытого
- Зафиксированы решения: вбиваем две цены и считаем процент; `familyId` не разбираем
  по позициям; узлы дерева — записи в БД с нашим названием; XML остаётся резервом
- `docs/api-reference.md`, `docs/data-model.md`, `docs/deployment.md`, `docs/app-structure.md`, `index.md`

**Окружение**
- `KASPI_MERCHANT_ID` в корневом `.env`

## 2026-08-12

**База знаний и правила**
- Заведены `index.md` (карта проекта), `CHANGELOG.md`, `STATUS.md`; `CLAUDE.md` сделан входным указателем
- `AGENTS.md`: правило п.9 «каркас поднимаю я, дальше код пишет пользователь», п.10 «новый код — сразу в документацию»
- `AGENTS.md`: разделы «Критерии качества», «Фиксация изменений кода в docs/», «Карта проекта и работа после /clear»
- `docs/roadmap.md` — roadmap на 10 этапов с детализацией доступов, Dashboard, Товаров, Заказов и автоматизации
- `docs/architecture.md`, `docs/api-reference.md`
- `.gitignore`: секреты, сборка, `node_modules`, IDE, skills внешних пакетов

**Каркас проекта**
- Монорепозиторий на npm workspaces: `server`, `front`, `shared`
- `shared`: роли и статусы пользователей, источники заказов, общие формы ответов API
- `server`: Express 5 + TypeScript, валидация окружения через zod, логгер, типизированные ошибки,
  единый обработчик ошибок, лог запросов, модуль `health`, graceful shutdown
- `front`: Next.js 16 (App Router), Tailwind 4, shadcn/ui на Base UI, Redux Toolkit + RTK Query,
  группы маршрутов `(shop)` / `(dashboard)` / `(auth)`, шрифт Inter с кириллицей

**База данных**
- PostgreSQL: база `radeya_mono`, роль приложения `radeya_app`, права на схему `public` ограничены
- Prisma 7 + драйвер-адаптер `@prisma/adapter-pg`, клиент в `server/src/db/client.ts`
- `GET /api/health` проверяет доступность базы, отдаёт 503 при недоступности

**Стили и темы**
- Подключён Sass; для своих компонентов — папка + `index.tsx` + `style.module.scss`
- Четыре темы в `front/src/styles/themes.css`: магазин и админка × светлая и тёмная
- Токены общих компонентов вынесены в `:root` и `.dark`, разделы переопределяют отличия
- Компоненты общие на всё приложение, деления по разделам нет; контракт: `className` через `cn()`,
  остальные пропсы через `...props`, внешние отступы задаёт вызывающая сторона
- Компонент-образец `PriceTag` (`front/src/components/price-tag/`)
