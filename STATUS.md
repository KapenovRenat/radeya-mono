# Текущее состояние

Ветка: **`feature/auth-dashboard`**. Дата среза: 15.09.2026.

## Как мы работаем

Правило изменилось по ходу работы, действующая версия — в [AGENTS.md](AGENTS.md):
**пользователь верстает, я пишу всю логику** — сервер, `shared/`, и логику фронта
(RTK Query, хуки, обработчики, роутинг) по запросу. Разметку и SCSS не трогаю:
если для логики нужна правка JSX, говорю словами, что подставить.

## Сделано

### Каркас и окружение

- Монорепозиторий npm workspaces: `server`, `front`, `shared`. Работает end-to-end.
- **Единый `.env` в корне.** Отдельных `.env` в пакетах нет. Как каждый пакет его
  находит — в [docs/deployment.md](docs/deployment.md).
- Готовых UI-китов нет: shadcn/ui, `tw-animate-css`, `class-variance-authority`
  удалены. Остались Tailwind (раскладка), Sass (компоненты), `cn()`, Lucide.
  `@base-ui/react` лежит в зависимостях без использования — на будущее, под модалки.
- SVG через SVGR (`@svgr/webpack` + правило в `next.config.ts`, `removeViewBox: false`).

### Маршруты фронта

```
/                        магазин, заглушка
/dashboard               сводка, проверка связи с API
/dashboard/login         вход сотрудника
/dashboard/accounts      Аккаунты и История (только ADMIN)
/dashboard/kaspi-sync    Синхронизация с Kaspi (только ADMIN)
```

Структура `dashboard/` с группами `(main)` и `(auth)`, зачем именно так —
в [docs/app-structure.md](docs/app-structure.md).

### Этап 1 — доступы (готово)

- Модели `User`, `Customer`, `Session`, `AuditLog`. Две миграции: `init_users`,
  `auth_sessions_audit`.
- Вход **по логину**, сессия в **httpOnly-куке**, состояние сессии в таблице —
  можно погасить мгновенно. Пароли argon2id (`@node-rs/argon2`).
- Отказ при входе всегда единый 401, без разделения «нет логина» / «неверный пароль».
  При несуществующем логине сравнение всё равно выполняется по фиктивному хешу —
  иначе разницу видно по времени ответа.
- `requireAuth`, `requireRole(...roles)`. На фронте `AuthGuard` и `RoleGuard` —
  это удобство интерфейса, настоящая проверка на сервере.
- Первый админ — **командой в терминале**, публичного эндпоинта регистрации нет:
  `npm run create:admin --workspace=server`.
- Раздел «Аккаунты»: таблица сотрудников, создание через модалку на нативном
  `<dialog>`, вкладка «История» с журналом действий.
- Журнал: `logAction()`, снимок логина и роли на момент действия, только вставка
  и чтение, сбой записи не роняет операцию.

### Синхронизация с Kaspi (предпросмотр, готово)

`POST /api/kaspi-catalog/preview` — разбор выгрузок `ACTIVE.xml` и `ARCHIVE.xml`
из кабинета. **В базу ничего не пишет**, только показывает результат.
На странице: загрузка файлов, счётчики, список складов, таблица по 100 строк,
фильтр «только с проблемами», неактивная кнопка «Сохранить в БД».

## Принятые решения (не пересматривать без причины)

| Решение | Почему |
|---|---|
| Сессии в таблице БД, не JWT | Уволил сотрудника — доступ закрывается сразу |
| Пароль сотрудника постоянный, без смены при первом входе | Решение пользователя. Следствие в рисках роадмапа |
| Первый админ только из терминала | Публичная форма регистрации однажды окажется открытой в проде |
| Клиенты магазина — отдельная модель `Customer` | У клиента нет роли и должности, права сотрудников к нему неприменимы |
| Статус продажи — в `MarketplaceListing`, не полем товара | Будут OZON и WB; поле у товара соврёт на второй площадке |
| Каталог Kaspi — из XML-выгрузки, не парсингом страниц | Стабильный формат вместо HTML; 1328 товаров сразу |
| Вход в кабинет Kaspi — **по номеру телефона** | С 16.09.2026 вход по email требует код с почты |
| Товар с модификациями: `Product` → `Variant` | Артикул и цена живут на модификации: Kaspi матчит заказы по артикулу |

Roadmap — три этапа: доступы, товары, заказы. Остальное в блоке «после 0–3»
с сохранёнными наработками. См. [docs/roadmap.md](docs/roadmap.md).

## Известные проблемы

**Не проверено пользователем:** создание сотрудника через модалку, запись в журнал,
разбор выгрузок Kaspi. Код написан, вживую не гоняли.

**В компонентах пользователя** (`front/src/components/input/`, `button/`,
`dashboard-nav-menu/`):
- `` cn(styles.X, `${className}`) `` — при отсутствии `className` в разметку
  попадает класс со словом `undefined`. Нужно убрать шаблонную строку.
- `className={styles.X}` стоит **после** `{...props}` — класс, переданный снаружи,
  теряется.
- `Input` не пробрасывает `id`, поэтому `<label htmlFor>` ни к чему не привязан.
- `Input` не ставит `aria-invalid` — красная рамка из SCSS не срабатывает.

**Прочее:**
- В выгрузке Kaspi нет картинок, штрихкодов и скидок — только парсером.
- `shared` отдаёт TypeScript-исходники. Для разработки хватает, для продакшен-сборки
  нужен бандлер (`tsup`).
- Пароль `radeya_app` слабый — локально допустимо, для сервера нужен длинный случайный.
- `prisma migrate dev` требует у роли право `CREATEDB` (shadow-база).
  На проде не нужно — там `migrate deploy`.
- `front/AGENTS.md` и `front/CLAUDE.md` может восстановить `next dev` — удалять.
- Директива `"use client"` пропадала из файла после автоформата IDE. Если Next
  ругается на хуки в серверном компоненте — проверить первую строку.
