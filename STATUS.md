# Текущее состояние

## Сделано

**Каркас работает end-to-end:** браузер → Next.js → Express → PostgreSQL.
`http://localhost:3000/dashboard` показывает статус API и базы, `GET /api/health` отвечает `ok`.

**Правила и документация**
- `AGENTS.md` — конституция: роль, правила поведения (10 пунктов), критерии качества,
  порядок фиксации кода в `docs/`, ведение карты проекта после `/clear`
- `index.md` — карта проекта: эндпоинты, методы, модели, страницы, компоненты, общие функции
- `docs/roadmap.md` — 10 этапов, сайт-магазин последним, детализация ближайших этапов
- `docs/architecture.md` — структура монорепозитория, слои, решения по стеку
- `docs/api-reference.md` — контракты эндпоинтов
- `docs/kaspi-api-integration.md`, `docs/telegram-bot.md`, `docs/analytics-spec.md` —
  справочники по внешним API из предыдущего проекта

**Код**
- Монорепозиторий на npm workspaces: `server`, `front`, `shared`
- `server` — Express 5, TypeScript, zod-валидация окружения, логгер, типизированные ошибки,
  единый обработчик ошибок, лог запросов, модуль `health`, корректная остановка
- `front` — Next.js 16 (App Router), Tailwind 4, shadcn/ui на Base UI, Redux Toolkit + RTK Query,
  группы маршрутов `(shop)` / `(dashboard)` / `(auth)` с раздельными layout и токенами стилей
- `shared` — роли, статусы пользователей, источники заказов, формы ответов API
- База `radeya_mono` и роль `radeya_app` созданы, Prisma 7 подключена через `@prisma/adapter-pg`

## В работе / следующий шаг

**Этап 1 — доступы.** С этого момента код пишет пользователь, я ставлю задачи (п.9).

1. Модель `User` в Prisma и первая миграция — поля, роли, статусы, индексы
2. Регистрация: первый пользователь становится админом (проверка и вставка в одной транзакции)
3. Вход и выход: сессия в httpOnly-куке, пароли через argon2
4. Мидлвары `requireAuth` и `requireRole`
5. Раздел «Пользователи»: список заявок, подтверждение, назначение роли
6. Журнал действий — с самого начала, задним числом не восстановить
7. Фронт: формы входа и регистрации, экран «ожидайте подтверждения», защита разделов

## Известные проблемы

- Схема БД пуста — моделей нет, миграций нет
- Сборка `shared` для продакшена потребует бандлера (`tsup`): сейчас пакет отдаёт TS-исходники.
  Для разработки достаточно, для деплоя — нет
- Пароль `radeya_app` слабый — допустимо локально, для сервера нужен длинный случайный
- `front/AGENTS.md` и `front/CLAUDE.md` может восстановить сам `next dev` — если появятся, удалять
- Формат XML-прайса Kaspi не подтверждён, нужен доступ к кабинету
- Ждут ответов от бизнеса: статусы заказов и маршрутизация в Telegram, структура РНП,
  список поставщиков — см. раздел 9 в `docs/roadmap.md`
